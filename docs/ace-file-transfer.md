# 文件传输：取出码 + Redis 旁路 blob

> **状态：设计记录，尚未实现（TODO）。** 这不是契约，也不是承诺；实现前需要单独一轮真实会话评测。

## 目标

一个 agent 把**本地文件**传给另一个 agent，而**文件内容不进入任何模型的上下文**。

## 为什么不做"把文件塞进事件 body"

事件 `body` 是一个流字段 ✓（能放二进制 ✓、单值上限 512 MiB ✓），但：

- body 会**整段进入接收方的模型上下文** ✗ —— 几十 KB 就毁掉上下文；
- 事件是 at-least-once ✓（会重投 ✓）→ 大 body 会被反复注入 ✗；
- 只有几 KB 才实用 ✗。

## 采用的设计（取出码）

**内容走 Redis 键 ✓；通知由模型自己转达 ✓（本功能不发 ACE 事件）。**

1. 发送方：`ace_send_file(path=…, ttl=…)` 读本地文件 → **在每个活跃 server 上各存一份**：
   `SET <该 server 的 ns>:xfer:<token> <binary> EX <ttl>`（`token` 为 128-bit 随机值，**键名即凭证**），
   外加一枚**元数据旁键** `<该 server 的 ns>:xfer:<token>:meta`（`{name, size, sha256}`）。
   工具**只返回**一行可原样转达的取件信息，不发布任何事件：
   `pickup=<token> size=… sha256=… expires_in=… stored_on=<server,server>`
2. 转达：由**模型自行**把这行信息告知目标 agent（走既有的 `ace_publish` 或任何渠道）。
   取件码就是 **token**（不含 namespace、不含 server 名 —— 短、不易传错）。
3. 接收方：`ace_get_file(token=…)` → 在**自己的**每个活跃 server 上按 `<自己的 ns>:xfer:<token>` 找 →
   第一台命中的即取（`GET`，**非破坏性** ✓：同一取件码在 TTL 内**任何人可取** ✓，只有过期才取不到 ✓）→
   连同一并取回 `:meta` → 写入**隔离目录** `.ace/xfer/<token>/<sessionId>/<name>`
   → 由 agent/用户决定之后怎么用。
   **工具不做校验裁决** ✓：它**算出并返回** `sha256=`、写入路径与取自哪台 server ✓，
   由 agent 与发送方给的哈希自行比对 ✓（有了 `:meta` ✓，接收方可以**自己核对** ✓，不必只信转达的文本 ✓）。

TTL：**ISO 8601 duration** ✓（默认 `PT1H`，上限 `P1D`）。

## 硬性安全规则（实现时必须遵守）

- **绝不允许由事件或调用方指定任意写盘路径** ✗✗ —— 否则任何对面 agent（或伪造 sender）都能覆盖你的文件。
  只能写进隔离目录；移到别处是**人/agent 的决定**。
- **`<name>` 净化** ✓：只取 basename ✓、剥掉路径分隔符与控制字符 ✓、拒绝 `..` ✓；原始文件名只作元数据记录 ✓。
- **大小上限** ✓：默认 **8 MiB**、硬上限 **64 MiB**（可配 `maxTransferBytes`）；**≥512 MiB 一律拒绝**（Redis 单值硬顶）。
  上限是**每份副本**的；存 N 份就是 N × 该大小。
- **sha256** 只保完整性、不保真实性 ✓（哈希由同一个不可信 sender 提供 ✓）。
- 键名带 namespace ✓（`<ns>:xfer:<token>` ✓），与 `<ns>:ch:<channel>` 同族 ✓。
- **信任策略照旧** ✓：取件信息是一条"另一个 agent 的说法" ✓（由模型转达 ✓）→ 取件前仍需用户批准该 sender ✓。
- **`send` 不限制读取范围**（本轮决定 ✓）：即 agent 可以把 `~/.ssh/id_rsa` 这类文件寄出 —— **记录为已知风险** ✓。

## 明确不做（至少 v0.1 不做）

- 不是通用文件同步 ✗：无分块、无断点续传（>512 MiB 需分块键 `xfer:<id>:0..N` 或换对象存储）；
- **不加密** ✗：同一 broker 上的他人可读明文；要私密需自带 AES-GCM 且密钥另路传递（v0.2 议题）；
- 取件码只防**猜** ✓，不防**有 Redis 权限的人** ✓ —— 与现有 channel 的安全模型一致；
- 不是 ack/回执机制 ✗（回执是另一件事，见 v0.2 讨论）；
- **取消** ✗：不做 —— 键靠 TTL 自然过期；
- **计数/统计** ✗：不做。

## 已定

1. **blob 落在哪台 server**：**在每个活跃 server 上各存一份**（发送方自己的配置）。
   接收方**不需要 namespace 指令**：它只按 token，在**自己的** server 上找。
2. **多人取件**：同一取件码在 TTL 内**任何人都可取**（`GET` 非破坏性，不用 `GETDEL`）。
3. **`<name>` 净化**：见上（只取 basename、剥分隔符与控制字符、拒绝 `..`）。
4. **`send` 读取范围**：暂不限制（风险已记录）。
5. **双工具**：`ace_send_file` / `ace_get_file`（一动词一工具）。
6. **大小上限**：默认 8 MiB、硬上限 64 MiB、≥512 MiB 拒绝（每份副本）。
7. **TTL**：默认 `PT1H`、上限 `P1D`；ISO 8601 格式。
8. **token 即凭证**：128-bit 随机；"谁拿到谁可取"写入工具文本。
9. **不发事件**：`send` 只返回取件信息，由模型转达。
10. **`get` 不校验哈希**：只负责取件与落盘，并返回它算出的 `sha256`（以及 `:meta` 里的那份）供 agent 比对。
11. **取消 / 计数**：不做。
12. **`get` 永不自己发起**：取件永远是显式调用。
13. **取件码就是 token**（不含 namespace、不含 server 名）。
14. **落盘路径带会话 id**：`.ace/xfer/<token>/<sessionId>/<name>`（同机多会话不撞车）。
15. **`send` 没有"给谁"参数**：由模型转达。
16. **元数据旁键**：`<ns>:xfer:<token>:meta` = `{name, size, sha256}`，接收方据此可自行核对。
17. **不定义成功/失败语义**：`send` 只在结果里**写明在哪些 server 上保存成功**（`stored_on=`）；
   由 agent 自行判断"够不够"。
18. **`server` 参数取消**：`ace_send_file(path=…, ttl=…)`，永远是"所有活跃 server 各存一份"。
19. **副本数暂不限制**：上限是每份副本的大小；多 server 的成本**记录在案**（N 份 = N × 大小）。
20. **多台命中取第一台**：并在结果里返回 `from=<server>` 便于排查。
21. **两边没有共享 server ⇒ 必然取不到**：这不算异常，而是可诊断的结局 —— 错误文案要说清
   「你的每台 server 上都没有该 token：可能已过期，或对方与你没有共享的 server」。

## 待定（只剩实现时的形态/边界细节）

1. **`path` 怎么解析**：相对 cwd ✓ 还是必须绝对 ✓？已定 4 说明不限制越出 workspace，所以只是"怎么读"的问题。
2. **`name` 要不要单独参数**：默认取文件的 basename；若发送方想改名，才需要 `name=`。
3. **零台接受时 `send` 返回什么**：按已定 17 —— 只报事实（`stored_on=` 为空 + 各台的失败原因），不定义成败。
4. **`:meta` 缺失但 blob 在**（blob 与 meta 是两次写，不是原子的）：报错，还是按"无元数据"继续？
   倾向报错并提示可能是一次中断的写入；同时考虑用 pipeline 把两次写的窗口压到最小。
5. **同一会话用同一 token 取两次**：同路径覆盖（字节相同）✓ 还是另开目录 ✓？
6. **`path` 指向目录 / 不存在 / 不可读**：三种都要有明确报错（不让它变成一次 0 字节的传输）。
7. **权限与前置条件**：发送方需要 `SET`、接收方需要 `GET`；是否把这条写进工具文本（便于排查权限问题）。
8. **`:meta` 里要不要带 `createdAt` / `expiresIn`**：接收方据此判断"这文件多新"。

## 验收计划

两个真实会话互传真实文件（中文 + 二进制各一），断言：接收方隔离目录里的字节与源文件一致 ✓、
**两个会话用同一取件码都能取到** ✓、`get` 返回的 `sha256` 与 `:meta`／发送方给的一致 ✓（比对由 agent 做 ✓）、
**只共享一台 server 的两个 agent 也能取到** ✓、超过上限时明确报错 ✓、TTL 过期后取件失败 ✓、
**每台 server 上都没有该 token 时给出可诊断的错误** ✓。
